# Avila GUI feature inventory — 2026-10-16

This is a source-based functional inventory of the current Avila GUI, compared with the stable Bitcoin Core GUI release **31.1**. The upstream comparison is pinned to the [`v31.1` release tag](https://github.com/bitcoin/bitcoin/tree/v31.1/src/qt); the official [31.1 release page](https://bitcoincore.org/en/releases/31.1/) and [release index](https://bitcoincore.org/en/releases/) identify that release. Source links below use the immutable tag, not `master`.

**Baseline and follow-up:** the gap inventory below was first captured against Avila source revision [`f59b690`](https://github.com/Connoravila1/Avila-Node/commit/f59b690), before the current block-inspector and operator-shell work. The “Implementation follow-up” records current-branch source additions so baseline absence statements are not mistaken for current status. The undo-inspector source passed the guarded workspace gate: 1,172 Rust tests (86 GUI tests, five ignored), 17 Python tests, formatting, all-target Clippy and rustdoc with warnings denied, paired release CLI/GUI builds and smoke checks. The 2,560 MiB cap / 1,024 MiB reserve run peaked at 2,031 MiB in 319 s. Source fingerprint SHA-256: `b8d1e8aad825943419f4e7fc25bb46e01387dd91c0d3169c8ef97a0c41458f2c`; installed CLI SHA-256: `9fa0079142f80ea292fc4bbd6bff213755ecf7dd31491e2ca991645a480b7d0d`; installed GUI SHA-256: `b0ee9470af909e3622fdd0df7395f13aa3f54dfd62ed5f3c563a0a3d5a4aae0c`. Native checks exercised attached block inspection, amount rendering, pagination, and GUI-close/daemon continuity; the result limits are recorded below. Two Avila fixture screenshots, five Bitcoin Core 31.1 menu screenshots, and attached-mode screenshots were reviewed on 2026-10-17.

### Historical input amounts and fees — gate and native check completed

Current source adds undo-derived amounts to the selected-transaction detail path.
The query remains pinned by block hash, txid, and transaction index, and reads
only matching active-chain undo; it does not use current UTXO state, txindex, or
peer fetches. The node returns at most 100 requested input values, while input
total and fee account for all inputs and outputs with checked range arithmetic.
The GUI labels `block_undo` as the value source and shows fee rate from measured
weight (`ceil(weight / 4)` virtual bytes). Coinbase amounts/fees, unavailable or
non-active-chain undo, hash mismatch, size-limit rejection, malformed records,
and inconsistent sums remain unknown. This display does not elevate script-
validation or snapshot-coverage status.

The guarded workspace gate and native attached-node check passed; evidence and
limitations are recorded above and in the [experiment note](../experiments/2026-10-17-undo-inspector-amounts.md).
Existing databases are not backfilled. Persisted lookup
stays disabled while admission metadata fails to cover any retained undo record,
or the sticky record maximum exceeds 8 MiB; adding admitted new rows alone does
not repair incomplete historical coverage. Recent in-memory tail/run undo
remains eligible. Once persisted-table coverage is complete and its global
maximum is within 8 MiB, the selected row is still checked against recorded size
and block hash before scanning at most 8 MiB. That is an encoded parser/input
bound, not a physical or RSS guarantee: ordinary redb page access may exceed the
record limit. The earlier block 83018 captures show the pre-change unknown-fee
state; block 255048 demonstrates the current unknown state when persisted
coverage is incomplete. No validation-completion or sync-speed claim follows
from this change.

The source/binary GUI checks described above passed at default 100% scale for 760×600 and 1440×900. The earlier 130%/200% responsive checks and direct keyboard row-focus sequence remain scoped as stated above. Live native paging verified five input pages for one 440-input transaction with backward navigation; a separate active transaction showed one input amount and fee. The first detail request's timeout recovered only after explicit row reselection. Screen-reader behavior, missing-cookie recovery, >100-output paging, nonzero-fee native rendering, delayed native RPC behavior, and cross-platform behavior remain unverified. This is not a full visual/accessibility audit.

### Remaining gaps after these additions

The new detail path shows bounded inputs/outputs and native-proven undo-derived amounts for one sample; persisted availability still depends on complete admission coverage, and nonzero-fee native rendering is unverified. Scripts remain prefix-limited and there is no fee distribution visualization. The attached mode adds a bounded read-only RPC console, while the GUI-owned mode still has no equivalent console. An explicit reorg timeline or branch graph and wallet workflows (send/receive, address book, backup, encryption, passphrase management, coin control or PSBT) remain absent. These are distinct from the present block summary/map and network traffic paths.

### Menu inventory in plain terms

Core 31.1’s wallet-enabled native GUI has **File** (wallet lifecycle/backup/restore, URI, sign/verify, PSBT, exit), **Settings** (wallet encryption/passphrase, value masking, Options), **Window** (minimize and debug tabs, plus wallet address windows), and **Help** (command-line options, About). The native no-wallet captures confirm these menu labels: File shows Create/Open/Migrate/Restore and PSBT load; Close/Backup, URI, Sign/Verify are disabled. Settings shows Mask values and Options, while Encrypt/Change Passphrase are disabled. Window shows Information, Console, Network Traffic and Peers, with sending/receiving-address windows disabled. Help shows Command-line options, About Bitcoin Core, and About Qt. Since no wallet was created, these captures confirm menu presence/disabled state only, not wallet lifecycle or transaction behavior. See the pinned [upstream menu implementation](https://raw.githubusercontent.com/bitcoin/bitcoin/v31.1/src/qt/bitcoingui.cpp#L487-L571).

Avila’s normal shell exposes **pages**, not a comparable menu bar: navigation is in the rail, with start/stop in status controls and node configuration in Settings/Config. The optional classic skin has File/Options/Help/Node, but no wallet operations; its apparent Send Coins and Address Book buttons only display original bitmap assets and have explanatory hover text. This distinction matters because a screenshot of the classic skin can suggest features that do not exist.

## Block visualization: recommended scope

The baseline inventory identified an **inspectable block view** as a P0 gap; the current branch implements block search/navigation, measured header/body facts, paged transaction summaries, a weight-proportional slice-and-dice map, and bounded selected-transaction details (see implementation follow-up). Avila also has a chain-level ribbon for chain coverage and validation status, while the overview shows a fee staircase for the prospective next block. The Core captures are menu/overview captures, not evidence about block composition. In the pinned v31.1 Qt source routes reviewed for the menu, overview, and debug window, no block-browser or block-treemap workflow was identified; treat Avila's map as a product feature rather than a claim of Core parity.

Implemented scope and remaining work:

1. **Implemented and natively exercised:** recent blocks open an inspector with height/hash search and adjacent navigation; header facts, measured size/weight/transaction count, and body availability are shown. Transaction summaries load in 100-item pages and are capped at 2,000 displayed rows. For loaded transactions, a slice-and-dice map gives rectangle area proportional to measured transaction weight; map and keyboard-table selection share the transaction-detail view. Header/framing weight is excluded from the loaded-transaction denominator and partial coverage is labeled.
2. **Implemented with explicit limits:** selected transaction details include up to 100 inputs and 100 outputs per response, outpoints, bounded script/witness prefixes, output values and addresses when available. Native checks showed input values, total fee and sat/vB for a zero-fee active-chain sample, plus reasoned unknown amounts when persisted undo admission is incomplete. Existing databases are not backfilled; persisted lookup remains disabled until admission metadata covers the entire retained undo table. Native checks exercised all input pages for a real 440-input transaction, including backward navigation; >100-output paging, nonzero-fee rendering, automatic retry after timeout and delayed RPC remain unverified.
3. **Remaining:** fee distribution visualization; fuller script display or expansion may need a deliberate size/privacy policy. A retained branch/reorg timeline requires branch identity and event history with defined retention. Do not infer it from tip movement. Show best-header candidates and active validated chain separately; snapshot-assumed coverage remains distinct from replay-proven coverage.

For any future timeline, chart or block glyph, preserve the repository’s own GUI requirements: measured source, explicit unknown/stale/disconnected states, text/keyboard alternatives, and separate meanings for header acceptance, active-chain connection, script validation, snapshot assumption, and local mempool policy ([docs/GUI.md](GUI.md#acceptance-requirements)).
